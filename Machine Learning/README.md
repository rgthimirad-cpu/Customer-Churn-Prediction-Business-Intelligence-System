## Group 4: Machine Learning

This directory contains the machine learning component of the Customer Churn Prediction & Business Intelligence System.

The objective of Group 4 was to develop, compare, tune and select a machine learning model capable of predicting customers who are at risk of churn and providing churn probabilities for downstream business applications.

---

## 1. Dataset

The machine learning models use the feature-engineered dataset produced by Group 3:

`Feature Engineering & Statistical Analysis/outputs/customer_churn_feature_engineered.csv`

Dataset size:

- 7,043 customer records
- Target variable: `Churn Value`
- 21 core predictive features

The target distribution is imbalanced, with approximately:

- 73.5% non-churn customers
- 26.5% churn customers

---

## 2. Leakage Protection

The following variables were excluded from model training because they contain direct or post-outcome churn information:

- `Churn Label`
- `Churn Score`
- `Churn Reason`

The final modelling pipeline uses only approved predictive features.

---

## 3. Experimental Strategy

A common modelling protocol was used across model development:

- 80% training data
- 20% held-out test data
- Stratified train/test split
- `random_state = 42`
- 5-fold `StratifiedKFold` cross-validation

The held-out test set was reserved during model development and was not used to select the final model.

---

## 4. Evaluation Metrics

Models were evaluated using:

- Accuracy
- Precision
- Recall
- F1-score
- ROC-AUC
- Confusion Matrix

Accuracy was not used as the only model-selection criterion because the churn target is imbalanced.

Particular attention was given to Recall and F1-score because failing to identify a genuine churn customer may prevent the business from taking an appropriate retention action.

---

## 5. Models Developed

Four model families were developed by Group 4:

| Member | Model |
|---|---|
| Member 1 | Logistic Regression |
| Member 2 | Decision Tree |
| Member 3 | Random Forest |
| Member 4 | XGBoost |

A DummyClassifier was also used as a no-skill baseline during Logistic Regression development.

---

## 6. Cross-Validation Model Comparison

The final model decision was based primarily on cross-validation results.

| Model | Accuracy | Precision | Recall | F1-score | ROC-AUC |

| Tuned XGBoost | 0.8136 | 0.6776 | 0.5692 | 0.6184 | 0.8632 |

---

## 7. Final Model Selection

### Selected Model: Tuned Logistic Regression

Tuned Logistic Regression was selected as the final model.

It achieved the highest cross-validation F1-score while maintaining high churn Recall and strong ROC-AUC.

Weighted XGBoost produced marginally higher Recall and ROC-AUC, but Logistic Regression provided a slightly stronger overall Precision-Recall balance and the highest F1-score.

Logistic Regression also offers a relatively simple and interpretable modelling approach and can be deployed together with its preprocessing stages through a single scikit-learn Pipeline.

The final model was selected using cross-validation results rather than held-out test performance.

## 9. Final Deployment Pipeline

After recording the held-out test performance, the selected pipeline was refitted using the complete available modelling dataset.

The final reusable model is stored as:

`models/final_churn_pipeline.joblib`

The saved pipeline includes both preprocessing and the Logistic Regression classifier.

This allows new customer records to be passed directly to the pipeline without performing preprocessing manually.

Example:

```python
import joblib

model = joblib.load(
    "models/final_churn_pipeline.joblib"
)

predicted_class = model.predict(new_customer_data)

churn_probability = model.predict_proba(
    new_customer_data
)[:, 1]

## 10. Prediction Output

Customer-level churn prediction results are stored in:

`outputs/churn_predictions.csv`

The prediction output contains the following information:

- Actual churn status
- Predicted churn class
- Churn probability
- Churn risk category

The `Churn Probability` value represents the estimated probability that a customer will churn.

For easier downstream business interpretation, customers are also grouped into descriptive risk categories:

- **Low Risk** – lower predicted churn probability
- **Medium Risk** – moderate predicted churn probability
- **High Risk** – higher predicted churn probability

These risk categories are intended to support business segmentation and dashboard reporting. They should not be interpreted as statistically optimized classification thresholds.

The churn probability output can be used by downstream components such as prediction interfaces, dashboards, retention analysis and business intelligence reporting.

## 14. Reproducibility and Data Leakage Prevention

Several controls were used to improve reproducibility and reduce data leakage.

A fixed random seed was used during model development:

`random_state = 42`

The modelling dataset was divided using an 80/20 stratified train/test split so that approximately the same churn distribution was maintained in both datasets.

Model development and hyperparameter selection were performed using the training data and cross-validation.

The held-out test set was reserved for final evaluation after the model-selection decision.

Five-fold `StratifiedKFold` cross-validation was used to provide a more reliable estimate of model performance across different training and validation subsets.

Preprocessing operations were included inside machine learning pipelines. This ensures that transformations such as scaling and categorical encoding are learned from the appropriate training data rather than globally before model validation.

The following leakage-related columns were excluded from the predictor set:

- `Churn Label`
- `Churn Score`
- `Churn Reason`

The final deployment pipeline was refitted on the complete available modelling dataset only after the held-out evaluation had been completed and recorded.

## 15. Business Use and Handoff

The final machine learning model is designed to support customer churn identification and downstream business decision-making.

The model produces both:

- A predicted churn class
- A churn probability score

The churn probability is especially useful because customers can be ranked according to their estimated churn risk instead of relying only on a binary churn/non-churn prediction.

Potential downstream applications include:

- Customer churn dashboards
- High-risk customer identification
- Retention campaign prioritization
- Customer segmentation
- Prediction interfaces
- Business intelligence reporting
- Retention strategy analysis

Customers with higher predicted churn probabilities can be prioritized for further investigation or retention actions.

The model prediction should be treated as a decision-support signal rather than a guarantee that an individual customer will churn.

The final saved pipeline:

`models/final_churn_pipeline.joblib`

can be loaded by downstream project components to generate churn predictions and probability scores for compatible customer records.

The customer-level prediction output:

`outputs/churn_predictions.csv`

can also be used directly by dashboard and business intelligence components.
